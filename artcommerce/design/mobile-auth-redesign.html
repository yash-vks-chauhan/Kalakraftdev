Mobile viewport · below the lg breakpoint

The sign-in screen a phone actually gets is the plainest screen we ship.

Everything that makes Kalakraft feel handmade — the warm gradient, the rotating pieces, the artisan proof — lives inside lg:flex and never reaches a 390 px screen. This is a redesign of /auth/login and /auth/signup at mobile width, built on the shadcn primitives already in the repo. No component API changes. The prototype below is live — type in it.

02 — Findings

Eight things the phone loses, and what replaces each

Left column is the behaviour in the current build. Right column is the proposed replacement, numbered to match the pins on the Before screen.

01

The brand is desktop-only

The whole <aside> — gradients, mandala, rotating hero pieces, artisan stats — is hidden lg:flex. A phone gets a 48 px logo strip and a white page.

A 230 px brand crown

The same gradient stack, mandala pattern and rotating Cloudinary pieces, sized for a phone. Same assets, same art direction, no new images to ship.

02

Sign-in and sign-up are separate routes

Switching costs a full client-side navigation, unmounts the form, and drops whatever the person had already typed.

One screen, a segmented switch

Both flows in a single mounted component. The email carries across the switch, so a mistyped destination costs one tap, not a re-type.

03

Roughly 180 px of dead space

The form is top-aligned inside h-svh, so on any tall phone the bottom third of the screen is empty and the footer floats mid-air.

Crown, sheet, action bar

Three bands that each own their height. Nothing floats: the sheet takes the remaining space and scrolls internally when it runs out.

04

The CTA scrolls away under the keyboard

The submit button lives inline. On a 667 px screen with the keyboard up, it can sit below the fold — the person types, then has to hunt for the button.

A sticky action bar

The primary button is pinned above safe-area-inset-bottom. Tap Keyboard open on the prototype: the crown collapses, the form scrolls, the button stays.

05

Social sign-in is buried

Google and Facebook sit below a divider, below the form, in a grid-cols-1 stack — last on the page for the path most people take.

OAuth first, email below

Full-width 48 px provider buttons above the fold, then or use email. The email form is still complete, just second.

06

Validation is end-loaded

Errors arrive after submit. The strength meter only appears once a password exists, and nothing confirms a valid email.

Feedback while typing

A tick when the email parses, requirement chips that fill in as they're satisfied, and a match line on confirm. The scoring function stays exactly as written in signup/page.tsx.

07

The proof never reaches mobile

200+ artisans, 20+ countries, 5,000+ collectors — all inside the desktop panel. A first-time buyer on a phone sees no reason to trust the form.

One condensed trust row

The same three numbers on a single 40 px line under the fields. Present, quiet, not a second hero.

08

Nothing moves

Below lg the only animation on the screen is the button's colour transition. The screen reads as a form, not as part of a craft brand.

Four deliberate moments

Crown slides, sheet lifts, segmented thumb glides, success check draws. Everything else stays still — and all of it is off under prefers-reduced-motion.

04 — Specification

Motion, accessibility, and what changes on disk

Motion budget

  • Crown collapse — 420 ms, cubic-bezier(.22,1,.36,1), on :focus-within
  • Segment thumb — 340 ms transform, never width
  • Hero cross-fade — 1.4 s opacity, 6.5 s interval, same as desktop
  • Success check — 550 ms stroke draw, fires once
  • Everything above is disabled under prefers-reduced-motion

Accessibility

  • Every control clears 44 × 44 px — the .auth-shell rules already handle this
  • Inputs stay at 16 px so iOS Safari never zooms
  • Segmented switch is a real role="tablist", arrow-key navigable
  • Errors are role="alert"; the splash is aria-live="polite"
  • Crown text sits on a veil that holds 4.5:1 against every hero slide

Files this touches

  • app/auth/AuthShell.tsx — add the mobile crown and the sticky slot
  • app/auth/_components/AuthBits.tsx — add the meter, chips, tick
  • app/auth/login/page.tsx, signup/page.tsx — feed one shared pane
  • Desktop lg: layout is untouched — every change is behind a mobile query

Deliberately not doing

  • No new colour tokens — the shadcn neutrals in globals.css stay as they are
  • No animation library; the existing framer-motion bundle isn't loaded on this route
  • No change to auth logic, Firebase calls, or the OAuth redirect handling
  • No merge of the two routes — both URLs keep working, they just share a pane
